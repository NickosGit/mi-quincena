- Decided (F3): `regexRows` pairs the k-th date with the k-th amount on each line; leftovers become rows with `null`. `checkCompleteness` returns `incomplete` when the raw text has more amounts than dates **or** any row has a null, so a structurer (F4) can't "fix" a missing date by inventing one. Unparseable dates ("31 nov", "L nov 2026") don't count as dates. A missing year resolves to the nearest date on or after today.

- Asked (F4): Nicolas asked "¿por qué con Gemini?". Answer: the packet and prompt specify Gemini's free tier, called from a server route, receiving text only. He chose to keep it.
- Decided (F4): the LLM may only **re-pair** what the regex reader found. `reconcile()` rejects the whole LLM output (→ regex rows, `source: "regex"`) unless its non-null amounts are exactly the regex amounts as a multiset, in cents. That way it can't drop, change or invent an amount, which also neutralizes "return amount 0" injections. Each LLM date must be one the regex found in the text, used at most as often as it appears; otherwise it becomes null. Then `checkCompleteness` runs on the final rows against the raw text, on the server and again in the browser.
- Decided (F4): no Gemini SDK, plain `fetch` to `generateContent` with `responseMimeType: application/json` + `responseSchema`, temperature 0, 20 s timeout, key in the `x-goog-api-key` header (never in the URL). The OCR text goes inside `<ocr_text>` with TODAY for year inference. "Today" on the server is computed in America/Mexico_City (Vercel runs in UTC).
- Decided (F4): rate limit of 20 calls / 10 min, in memory, per user id (or per IP for `demo: true`). Any non-200 from the route makes the browser fall back to the local regex reading, with the server's Spanish message shown as a note.
